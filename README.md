## 平台到底在查什么：三层信号，四层责任

平台判定多个账号是否属于同一经营者，看的是网络层、设备与浏览器指纹层、行为与业务层的信号重合度。网络层包括 IP 与 ASN、IP 类型标签、Fraud Score、时区地理一致性；指纹层有 40 项以上维度，从 Canvas、WebGL 到字体、分辨率、WebRTC 内网 IP；行为层看注册与上架节奏、提现规律、支付卡 BIN 与账单地址是否一致、商品图文相似度。

有一句话概括得很准：网络层是入场券，指纹层是身份证，行为层是行为艺术。绝大多数封店死在前两层。

但**账号关联不等于一定封店**。亚马逊的政策口径是：除非有合理业务需要且所有账户信誉良好，否则每个销售地区只允许保留一个卖家账户；合理业务需要包括拥有多个品牌并分别维护每个品牌的业务。真正容易导致封店的是利用多账号操纵销量或评论、违规账号继续注册新账号运营、违反卖家行为准则。合规的多账号可以共存，前提是主体真实独立。

把责任拆成四层，能省掉很多无效争论：

| 层级 | 典型重合项 | 工具能否解决 | 谁负责 |
| --- | --- | --- | --- |
| 主体层 | 公司、税号、收款账户、地址、邮箱、电话 | 基本不能 | 业务侧必须独立 |
| 网络层 | IP、DNS、网络提供商、WebRTC 泄露 | 可以解决 | 代理资源 + 配置 |
| 环境层 | 指纹、Cookie、缓存、时区、字体、语言 | 可以解决 | 指纹浏览器 |
| 行为层 | 商品目录、图片、文案、操作节奏、客服流程 | 只能部分辅助 | 运营 SOP |

2026 年的执法力度比前两年更紧。有第三方梳理称，亚马逊自 3 月启动专项扫号，采取品牌连坐，某一品牌下任一店铺违规，关联账号可能被永久封停，流出的名单包含 824 个品牌；8 月又开启全平台 AI 回溯核查，大量卖家收到援引《商业解决方案协议》第 3 条的停用通知，系统先限制账号，再由卖家举证。Temu 在 1 月升级处罚，任一店铺被评“较差”，关联店铺的上新权限会面临阶梯式处罚，最长 30 天冻结。TikTok Shop 的口径更直接：多个账号共享联系方式、付款信息、运营设备等任一项一致，就可能被认定关联。

这些规则背后是图神经网络做的关联图谱：账号是节点，多维信号是边，信号重合度是边权重。某个节点被标黑，它所在的连通分量全部纳入复核。判定还是回溯性的，历史数据全量存储并周期性重算。

深圳一个家居卖家收到三封停用邮件，理由都是“与已被停用的账号存在关联”。他三个店铺分属不同公司主体，独立 EIN、独立银行账户、独立收款、独立静态住宅 IP，配置已经比多数人认真。问题出在一台兼职电脑上：那台机器帮他上过 Listing，而它登录过一个三年前就被停用的老账号。新账号触发人工审核时，系统把十一个月前的历史图谱翻了出来。设备指纹的重合不会因为换公司主体而消失。

## IP 是入场券，但“住宅 IP”四个字不能信标签

决定风险的是出口 IP 的 ASN 和情报库标签，机器放在机房这件事本身不直接等于高危。把 IP 分三类，很多混淆就清楚了。

**机房广播 IP**：ASN 归云厂商，AWS、GCP、Azure、Vultr、DigitalOcean、Linode、Oracle 都算。情报库标签是 `Hosting` 或 `Datacenter`，rDNS 指向 `*.vultr.com`、`*.amazonaws.com` 这类域名。用这种 IP 注册 Amazon，通过率不到 5%，TikTok Shop 更低。搬瓦工这类常规 VPS 自建代理也落在这个区间，拿它跑主力店铺是给自己加难度。

**原生 IP**：WHOIS 注册国、广播地、物理所在地三者一致。它解决的是地理一致，不改变 IP 类型标签。原生机房 IP 依然是机房 IP。很多商家把原生 IP 当住宅 IP 卖，属于偷换概念。

**住宅双 ISP 静态 IP**：IP 段由 Comcast、AT&T、Verizon、Spectrum、Cox、Deutsche Telekom、Orange 这类住宅宽带 ISP 持有并广播，长期固定，情报库里同时被两个住宅 ISP 的 ASN 覆盖。双 ISP 更稳，是因为 MaxMind、IPinfo 对住宅属性的判定依赖多源交叉验证：该段的历史使用记录、上游 ISP 的 BGP 宣告、rDNS 是否指向住宅域名、是否被多个数据库同时标为住宅。单 ISP 住宅 IP 如果历史记录短，可能被标成 `Residential (Uncertain)` 而降权。

SixtyNet 的 Residential 系列官方标注 Residential IP，并且因为 IP 风控关闭了 80/443 入站端口，说明它确实在按住宅段做适配。但标签是商家给的，最终以你查到的 ASN 和情报库为准。买回来先验，别急着注册店铺。

### 五个能自己跑的验证指标

**1. ASN 与归属**

bash
curl -s "https://ipinfo.io/1.2.3.4/json"


看 `org` 是不是 Comcast、AT&T、Verizon、Spectrum 这类住宅 ISP。有 `type` 字段时必须是 `isp`，不能是 `hosting` 或 `business`。

**2. Fraud Score**

在 IPQualityScore 输入 IP，要求 `fraud_score < 30`，并且 `proxy`、`vpn`、`tor`、`recent_abuse` 全部为 false。这一项高，说明这个 IP 被大量滥用过，换段比换店铺资料更有效。

**3. rDNS 反向解析**

bash
dig -x 1.2.3.4 +short


结果应含 `hsd1`、`dyn`、`cable`、`dsl`、`ppp` 这类住宅特征，不应含 `compute`、`vps`、`cloud`、`server`。rDNS 是情报库判断住宅属性的输入之一，机房域名的反向解析很难洗白。

**4. 历史纯净度**

bash
curl -s "https://api.abuseipdb.com/api/v2/check?ipAddress=1.2.3.4&maxAgeInDays=90" \
  -H "Key: YOUR_API_KEY" -H "Accept: application/json"


要求 `abuseConfidenceScore < 10`，`totalReports` 越低越好。有历史举报记录的段，平台侧的风控评分会长期偏高。

**5. 静态性与独占性**

bash
for i in $(seq 1 7); do
  date '+%F %T'
  curl -s --proxy socks5h://user:pass@你的VPS:1080 https://api.ipify.org
  echo
  sleep 86400
done


连续 7 天定时查出口 IP，7 天输出必须完全一致。变化就是动态池，不能用来长期登录店铺后台。`socks5h` 里的 `h` 让 DNS 也走代理，顺手解决 DNS 泄漏。

五项里任何一项不过，先别注册店铺。IP 情报库的更新频率已经从周级提升到小时级，建议每月复检一次 Fraud Score，一旦升高就换 IP。

### 平台看 IP 的三个维度

平台早已不用“住宅 vs 机房”二分法。它看 ASN 归属、IP 的专属性与历史信誉、IP 与浏览器环境的地理自洽性。

专属性容易被忽略。廉价机房代理池可能只有几十个 C 段，几十个店铺实际共享同一段，隔离效果为零。一台 VPS 一个 IP 的好处在这里：出口固定，不跟陌生人轮换。

地理自洽性是硬约束。美国站配美国 IP，时区 `America/New_York` 或 `America/Los_Angeles`，语言 `en-US`。IP 在德国但时区填 `Asia/Shanghai`，指纹浏览器配置得再细也没用。

铁律只有一句：**一个店铺 = 一个独立静态 IP = 一个独立指纹浏览器环境 = 一套独立支付资料**。四者严格 1:1:1:1 绑定，任何交叉复用都会进入关联图谱。一个 IP 跑多个店铺是关联封店的经典死法，平台会把同一 IP 下所有账号视为同一主体，一个违规全部连坐。

## 指纹浏览器管不到的三层

指纹浏览器解决的是浏览器环境隔离。它把 Canvas、WebGL、字体、UA、时区、语言、WebRTC 这些维度虚拟化并锁定，让每个环境看起来像一台独立设备。但它管不了主体层、支付层和内容层。

一个团队每个店铺独立 IP、独立指纹，配置堪称教科书，但所有店铺绑定同一家公司的收款账户，发货地址填同一个海外仓编号，商品标题和五点描述用同一套模板。平台不需要看指纹，光主体和内容的重合度就足够并案。

指纹配置的核心是自洽和固化，不是随机。常见矛盾包括：UA 声明 macOS + Safari，WebGL 渲染器却返回 Windows 的 Direct3D 驱动字符串；分辨率 1920×1080，但 `devicePixelRatio` 是 3，通常只见于 Mac Retina；Canvas 特征指向 NVIDIA GPU，WebGL 参数却返回 Intel 集成显卡。过度随机化本身也是异常信号，参数组合的熵值会偏离真实设备分布。正确做法是在真实设备指纹分布里采样，把选中的组合持久化锁定，保证同一环境今天和三个月后启动返回同一套值。

两个隐蔽泄漏点要单独处理。WebRTC 走 UDP，ICE 候选收集会通过 STUN 拿到本地 IP 和 NAT 映射后的公网出口；HTTP 层走代理时，UDP 层仍可能绕过。只在 JS 层禁用 WebRTC 不够，网页可以检测 `RTCPeerConnection` 是否被异常禁用来反推指纹浏览器。DNS 泄漏同理：指纹浏览器要开启“DNS 走代理”，代理用 `socks5h` 而不是 `socks5`。

上线前的检测清单：

- whoer.net 匿名度 > 95%
- browserleaks.com/webrtc 无真实 IP 泄露
- browserleaks.com/dns 无本地 DNS 泄露
- browserleaks.com/canvas 指纹唯一
- ipinfo.io 的 ASN 为住宅 ISP
- ipqualityscore 的 `fraud_score < 30`
- amiunique.org 指纹唯一性 > 99%
- 时区、语言、IP 地理三者一致

## 支付链路：店铺活不活，最后卡在收款上

账号存活率可以拆成一个乘法：网络身份一致性 × 浏览器指纹独立性 × 支付链路洁净度。网络身份权重最高，但支付链路出问题，前两项做得再好也会归零。

PayPal 的隔离清单有六项：注册 IP 与店铺主体 IP 地理一致且为住宅 IP；登录 IP 长期固定；提现银行卡 BIN 归属国与 PayPal 注册国一致；账单地址与银行卡账单地址一致；手机号用目标国真实号码，Google Voice 已大量被标记，建议实体号；邮箱用 Gmail 或 Outlook，不用临时邮箱。

Stripe 额外看“网站主体”。网站必须真实运营，有隐私政策、退款政策、联系方式页面。IP 跳变加网站空壳，基本是秒封。

PayPal 冻结分三种。资料审核冻结，提交真实资料通常 3–7 天解冻；风控冻结，需要提供订单、物流、网站链接佐证，成功率看资料完整度；关联冻结，基本无解，只能换主体重开。2026 年支付卡 BIN 开始穿透到发卡行验证账单地址真实性，虚拟卡批量注册的做法已经失效。

## 按店铺价值分层，不要一律上最贵

隔离投入要和店铺价值匹配。试水店铺用入门档指纹浏览器加一台独立住宅 IP，先把流程跑通；成长店铺用付费档浏览器，按店铺数增加独立 IP；核心店铺再加云端安卓实例兜底，真实 ARM 设备从系统层就是独立设备，隔离完整性更高。

核心店铺要不要上云手机，按营收权重决策，不必一刀切。把有限的真实设备资源留给贡献最大的店，试水店用入门方案跑通，资源利用率最高。

## 常见问题

**机场节点能不能开店？**

不能。机场是共享 IP，几十上百人同时用，历史混乱，而且多为机房 ASN。用机场节点注册店铺，通过率很低，侥幸注册成功也容易在几天内被封。机场的正确用途是日常科学上网，和电商 IP 物理隔离，混用会污染住宅 IP。

**一个 IP 能不能跑多个店铺？**

不能。平台会把同一 IP 下所有账号视为同一主体，一个违规全部连坐。不同端口不等于不同 IP，出口相同就会被并案。

**指纹浏览器和 IP 哪个更重要？**

网络层权重最高，指纹层次之。只换 IP 不换指纹，或只换指纹不换 IP，都是半套防关联。两者必须同时到位，再叠加主体和支付隔离。

**IP 用久了 Fraud Score 升高怎么办？**

先复检，确认是 IP 段被滥用还是你的行为触发。升高明显就换 IP，不要等平台先动手。IP 情报库更新到小时级后，一个段的口碑变化很快。

**TikTok Shop 和 Amazon 能不能共用环境？**

不能。跨平台的数据共享在加深，同一 IP 同时登 Amazon 和 TikTok Shop，等于把两个平台的账号放进同一个连通分量。同一平台的不同店铺也要独立环境。

**住宅套餐的 80/443 端口关闭，会影响店铺登录吗？**

不影响。关闭的是入站端口，浏览器出站访问 443 正常。它只说明这些套餐不能拿来建公开网站，建站要选 LAX 系列。

**退款怎么算？**

公开测评提到退款窗口只有 3 天，部分住宅套餐退款只退到网站余额。下单前在结算页确认退款条款，别按 30 天无理由的惯性理解。
